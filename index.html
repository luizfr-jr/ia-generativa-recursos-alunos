1. Editar um cartaz com JSON

O que você vai aprender

Ao concluir esta seção, você deverá conseguir:

  • descrever os componentes visuais de uma imagem como dados organizados;
  • pedir a um modelo de IA uma representação JSON da estrutura visual;
  • conferir e corrigir esse JSON antes de usá-lo;
  • separar conteúdo, posição e estilo;
  • trocar um texto ou uma imagem sem reconstruir toda a composição.

A ideia central

Uma imagem comum contém pixels. Ela não guarda, necessariamente, camadas editáveis com nomes como “título”, “fundo” e “botão”. Portanto, quando pedimos a uma IA que “converta a imagem em JSON”, ela analisa o que aparece e produz uma descrição estruturada e aproximada da composição. O JSON é um mapa da imagem, não o arquivo original editável nem uma conversão perfeita.

A qualidade do resultado depende da resolução, da clareza da imagem e da capacidade do modelo de reconhecer elementos. Posições, fontes e cores podem ser estimadas; confira esses dados antes de usá-los. O JSON é um formato de dados definido por uma especificação, e não uma linguagem de desenho por si só.

Exemplo: mapear um card de 1200 × 675 pixels

Imagine uma peça horizontal com fundo claro, um pequeno rótulo laranja, um título azul-escuro e um parágrafo. Para descrevê-la, dividimos a imagem em uma tela e elementos. Cada elemento recebe um identificador, conteúdo, caixa de posição e estilo.

{
  "canvas": {
    "width": 1200,
    "height": 675,
    "background": "#f3f6fb"
  },
  "elements": [
    {
      "id": "eyebrow",
      "type": "text",
      "content": "AULA COMPLEMENTAR",
      "box": { "x": 96, "y": 78, "width": 440, "height": 38 },
      "style": {
        "fontFamily": "Arial, sans-serif",
        "fontSize": 18,
        "fontWeight": 700,
        "color": "#f05a28"
      }
    },
    {
      "id": "title",
      "type": "text",
      "content": "Criar com IA com mais controle",
      "box": { "x": 96, "y": 150, "width": 930, "height": 100 },
      "style": {
        "fontFamily": "Arial, sans-serif",
        "fontSize": 52,
        "fontWeight": 700,
        "lineHeight": 1.05,
        "color": "#0b2d56"
      }
    },
    {
      "id": "description",
      "type": "text",
      "content": "Transforme uma referência visual em dados e edite uma parte por vez.",
      "box": { "x": 96, "y": 285, "width": 840, "height": 72 },
      "style": {
        "fontFamily": "Arial, sans-serif",
        "fontSize": 24,
        "fontWeight": 400,
        "lineHeight": 1.35,
        "color": "#52647a"
      }
    }
  ]
}

As coordenadas acima são medidas a partir do canto superior esquerdo da tela: x cresce para a direita e y cresce para baixo. width e height definem o tamanho da caixa do elemento. A estrutura separa o que pode mudar — como content — do que deve permanecer estável — como box e style.

Passo 1 — Prepare a imagem de referência

  1. Use a imagem original, com a maior resolução disponível.
  2. Anote ou confira as dimensões em pixels e a proporção. Neste exemplo, 1200 × 675 corresponde a 16:9.
  3. Identifique os elementos principais: fundo, títulos, textos, imagens, formas, margens e alinhamentos.
  4. Se houver texto pequeno ou borrado, informe que ele deve ser marcado como ilegível ou incerto, em vez de inventado.

Passo 2 — Peça uma análise estruturada

Envie a imagem a uma ferramenta de IA com capacidade de analisá-la e use um pedido como este:

Analise esta imagem como referência para reconstruir sua composição em HTML e CSS. Devolva somente um JSON válido, sem bloco Markdown e sem comentários. Inclua as dimensões da tela e uma lista ordenada de elementos. Para cada elemento, informe id, tipo, conteúdo visível, caixa x/y/width/height em pixels a partir do canto superior esquerdo, cor, família e tamanho aproximado da fonte, peso, alinhamento e ordem de sobreposição quando for possível inferir. Não invente texto ilegível: use null e liste a incerteza em um campo “uncertainties”. Preserve as posições relativas e a hierarquia visual. Não escreva o código ainda.

A solicitação separa duas etapas: primeiro entender a referência; depois decidir como implementá-la. Isso facilita corrigir o mapa antes de gerar ou editar o código.

Passo 3 — Confira o JSON

Antes de usar a resposta:

  • confira se o JSON está sintaticamente válido: chaves e aspas devem estar pareadas, e não pode haver vírgula sobrando no fim de uma lista;
  • compare a largura, altura e proporção com a imagem de referência;
  • confira se a ordem dos elementos segue a leitura visual;
  • corrija coordenadas ou textos evidentes e marque como estimativas os valores incertos;
  • mantenha uma cópia do JSON original antes de fazer alterações.

Em JavaScript, JSON.parse() transforma uma string JSON válida em um objeto e lança um erro de sintaxe se o texto não obedecer à gramática esperada. Você pode usá-lo para detectar erros de formatação antes de renderizar a página.

const layout = JSON.parse(jsonText);
console.log(layout.canvas.width, layout.canvas.height);

Passo 4 — Separe o conteúdo da apresentação

O HTML define os elementos que aparecem. O CSS define a aparência e a posição. O JSON reúne os valores que queremos editar. Uma estrutura simples permite atualizar apenas o conteúdo de cada elemento identificado:

<div class="poster" id="poster">
  <p class="element" id="eyebrow"></p>
  <h1 class="element" id="title"></h1>
  <p class="element" id="description"></p>
</div>

.poster {
  position: relative;
  width: min(100%, 1200px);
  aspect-ratio: 16 / 9;
  overflow: hidden;
  container-type: inline-size;
  background: #f3f6fb;
}

.element {
  position: absolute;
  margin: 0;
}

#eyebrow {
  left: 8%;
  top: 11.5%;
  width: 36.7%;
  height: 5.6%;
  color: #f05a28;
  font: 700 1.5cqw/1.2 Arial, sans-serif;
}

#title {
  left: 8%;
  top: 22.2%;
  width: 77.5%;
  height: 14.8%;
  color: #0b2d56;
  font: 700 4.3cqw/1.05 Arial, sans-serif;
}

#description {
  left: 8%;
  top: 42.2%;
  width: 70%;
  height: 10.7%;
  color: #52647a;
  font: 400 2cqw/1.35 Arial, sans-serif;
}

function applyLayout(layout) {
  document.querySelector("#poster").style.background = layout.canvas.background;

  for (const item of layout.elements) {
    const node = document.getElementById(item.id);
    if (!node) continue;

    node.textContent = item.content ?? "";
    node.style.left = `${(item.box.x / layout.canvas.width) * 100}%`;
    node.style.top = `${(item.box.y / layout.canvas.height) * 100}%`;
    node.style.width = `${(item.box.width / layout.canvas.width) * 100}%`;
    node.style.height = `${(item.box.height / layout.canvas.height) * 100}%`;
  }
}

applyLayout(layout);

Neste exemplo, o programa converte as posições em pixels para porcentagens da tela. A proporção 16:9 é mantida conforme o card muda de largura, e os elementos continuam ancorados nos mesmos pontos relativos.

Passo 5 — Modifique um elemento sem deslocar os demais

Suponha que queremos atualizar o título. A mudança deve ocorrer no campo content do elemento com id title; as coordenadas, o tamanho da caixa e o CSS permanecem iguais.

Antes

{
  "id": "title",
  "content": "Criar com IA com mais controle",
  "box": { "x": 96, "y": 150, "width": 930, "height": 100 }
}

Depois

{
  "id": "title",
  "content": "Editar com IA sem perder a composição",
  "box": { "x": 96, "y": 150, "width": 930, "height": 100 }
}

A troca do texto não exige reposicionar o parágrafo ou reconstruir o card. Se a nova frase for mais longa e não couber, primeiro tente uma versão mais curta. Se isso não resolver, ajuste somente a caixa do título ou seu tamanho de fonte, verificando que os outros elementos continuem nos lugares originais.

Como pedir à IA uma alteração localizada

Depois de conferir a estrutura e o código, use uma instrução com limites claros:

Altere somente o conteúdo do elemento com id “title” para “Editar com IA sem perder a composição”. Preserve as coordenadas, as dimensões, as cores, a fonte, o fundo, a proporção da tela e todos os outros elementos. Não recrie o layout. Mostre quais campos foram alterados.

Uma instrução específica reduz alterações acidentais, mas não garante que o modelo obedeça perfeitamente. Compare sempre o resultado com a referência.

Lista de conferência

Antes de considerar a alteração concluída:

  • a tela continua com a mesma proporção da referência;
  • o título, o texto de apoio e os elementos visuais continuam alinhados;
  • nenhuma caixa foi movida sem necessidade;
  • o novo texto não ficou cortado, sobreposto ou pequeno demais;
  • cores, fontes e margens importantes foram preservadas;
  • o JSON continua válido e o código carrega sem erros;
  • o resultado foi comparado com a imagem original, lado a lado.

Limites e cuidados

  • A análise visual é uma estimativa: a IA pode não reconhecer a fonte exata, pequenos textos, espaçamentos ou transparências.
  • Uma imagem achatada não contém as camadas originais. O JSON descreve uma estrutura provável, que pode ser ajustada manualmente.
  • Alterar o texto pode mudar a quebra de linha. Reserve espaço suficiente ou edite a frase mantendo um comprimento parecido.
  • Uma edição generativa feita diretamente sobre os pixels pode modificar elementos vizinhos. Quando a posição precisa permanecer previsível, prefira reconstruir a composição com elementos HTML/CSS ou camadas editáveis.
  • Não use dados pessoais ou materiais com direitos restritos em ferramentas externas sem autorização.

Atividade prática

Escolha um card, slide ou cartaz simples que você possa usar como referência.

  1. Registre suas dimensões e proporção.
  2. Peça a uma IA para descrever a estrutura em JSON usando o prompt desta seção.
  3. Confira e corrija as caixas de três elementos: um rótulo, um título e um texto de apoio.
  4. Monte uma versão básica em HTML/CSS ou em uma ferramenta que permita editar camadas.
  5. Troque apenas o texto do título e compare as duas versões.
  6. Anote quais posições permaneceram iguais e qual ajuste foi necessário para evitar cortes.

Questão de reflexão: por que gerar uma nova imagem a cada alteração pode dificultar a preservação do layout, enquanto separar conteúdo, posição e estilo torna a edição mais controlável?

Referências técnicas

  • RFC 8259 — The JavaScript Object Notation (JSON) Data Interchange Format
  • JSON.parse() — MDN
  • CSS aspect-ratio — MDN

Exemplo interativo para testar

Abra o exemplo de cartaz com JSON no navegador. Ele apresenta a composição original e uma versão alterada lado a lado. No código, o layout é copiado e apenas o campo content de cada elemento é trocado; box e style são mantidos.

Resultado da verificação: as duas versões renderizam quatro elementos e mantêm iguais posições (x e y), dimensões (width e height) e estilos de cada elemento. O exemplo mostra que a separação entre conteúdo e geometria permite mudar o texto sem deslocar os elementos.

Limite observado: preservar as caixas não garante que qualquer texto caiba nelas. Uma frase mais comprida pode quebrar em mais linhas ou ser cortada. Nesse caso, encurte o texto ou ajuste de forma controlada a caixa ou a fonte, verificando novamente os demais elementos.

Este é um teste controlado com um layout já descrito em JSON. Na conversão de uma imagem real, a etapa de análise visual ainda precisa estimar as caixas, os textos e os estilos; esses dados devem ser conferidos antes da edição.

Abra o exemplo, escreva um novo título e veja se ele cabe na área reservada. Observe também se a descrição e o botão permanecem no lugar.

2. Aplicar o estilo de uma imagem a outra

A ideia

Nesta abordagem, não tentamos reconstruir a imagem de referência nem manter sua composição. Usamos a primeira imagem para descrever um estilo visual em JSON e aplicamos essa descrição a uma segunda imagem, que fornece o assunto ou conteúdo da imagem final.

  • Imagem de estilo: informa a aparência desejada — paleta, contraste, iluminação, textura, traço, atmosfera e tratamento visual.
  • Imagem de conteúdo: informa o que deve aparecer — pessoas, objetos, ambiente e, se desejado, composição geral.
  • JSON: funciona como uma ficha organizada de estilo. Ele não altera a imagem por conta própria; serve como especificação para orientar o pedido à ferramenta de geração ou edição.

Por exemplo: a imagem de estilo pode ser uma ilustração editorial com cores suaves e textura de papel; a imagem de conteúdo pode ser uma fotografia de uma equipe em laboratório. O objetivo é gerar uma nova imagem da equipe com aquele tratamento gráfico, sem copiar a cena da imagem de estilo.

Exemplo de ficha de estilo

A ficha abaixo é apenas um exemplo descritivo. Os valores devem ser preenchidos a partir de uma referência real e conferidos por uma pessoa.

{
  "style_name": "ilustração editorial suave",
  "palette": {
    "dominant": ["azul petróleo", "verde sálvia", "creme"],
    "accent": "coral suave",
    "saturation": "baixa a média"
  },
  "lighting": "difusa, suave, sem sombras duras",
  "texture": "grão fino semelhante a papel",
  "edges": "formas simplificadas, contornos discretos",
  "contrast": "baixo a médio",
  "mood": ["acolhedor", "didático", "contemporâneo"],
  "rendering": "ilustração editorial com volumes simples",
  "avoid": [
    "copiar os objetos da imagem de estilo",
    "adicionar texto ou logotipos não solicitados",
    "mudar a quantidade de pessoas ou objetos principais da imagem de conteúdo"
  ]
}

Fluxo de trabalho

  1. Escolha uma imagem de estilo e uma imagem de conteúdo. Identifique qual informação cada uma deve fornecer.
  2. Peça a um modelo com capacidade de analisar imagens para descrever somente as características visuais transferíveis da imagem de estilo em JSON. Não peça que copie os objetos ou a cena dessa referência.
  3. Revise a ficha: troque termos vagos por descrições observáveis, como “luz difusa” ou “textura de papel”, e remova características que não deseja aplicar.
  4. Envie a imagem de conteúdo junto da ficha e explique o que precisa permanecer reconhecível.
  5. Gere uma primeira versão, compare com as duas referências e ajuste a ficha ou as instruções em etapas.
  6. Confira se a ferramenta alterou acidentalmente elementos importantes, como quantidade de pessoas, objetos, detalhes clínicos, rótulos ou identidade visual.

Prompt para aplicar a ficha

Use a imagem 1 somente como referência de estilo e a imagem 2 como referência de conteúdo. Aplique à imagem 2 as características descritas neste JSON: [inserir a ficha]. Preserve o assunto principal, a quantidade de pessoas e objetos importantes e a leitura geral da imagem 2. Não copie a cena, os objetos ou a composição específica da imagem 1. Não acrescente texto nem logotipos. Gere uma nova interpretação visual e informe quais aspectos do conteúdo podem ter sido alterados.

Ferramentas de geração de imagem podem aceitar imagens junto com instruções em texto e realizar transformações de estilo; a documentação do Gemini, por exemplo, apresenta um fluxo de transferência de estilo com preservação da composição quando isso é pedido. O comportamento varia conforme a ferramenta, então o resultado precisa ser avaliado. Documentação oficial de geração e edição de imagens do Gemini

O que avaliar no resultado

  • O estilo visual da referência foi percebido (paleta, iluminação, textura, contraste e tratamento)?
  • O conteúdo importante da segunda imagem continua reconhecível?
  • Elementos da imagem de estilo foram copiados por engano?
  • O resultado acrescentou palavras, símbolos ou objetos que não foram pedidos?
  • Quais características do JSON parecem ter sido obedecidas ou ignoradas?

Importante: esse processo não garante uma transferência perfeita. O JSON deixa a intenção mais explícita e permite editar a descrição por partes, mas o modelo de imagem ainda interpreta as instruções de forma probabilística. Para avaliar a técnica mencionada no vídeo, vale testar a mesma imagem de conteúdo com e sem a ficha JSON e comparar os resultados.

3. Usar a identidade visual da marca

Objetivo

Usar um arquivo de identidade visual — como manual em PDF, apresentação de referência, arquivo de logotipo ou descrição escrita — para orientar a criação de peças diferentes sem perder a coerência da marca.

A IA deve consultar o material fornecido como fonte. Se uma regra não estiver clara ou não aparecer no arquivo, deve sinalizar a dúvida em vez de inventar uma cor, uma fonte, uma versão do logotipo ou uma aplicação.

Etapa 1 — Transforme o manual em uma ficha consultável

Envie o manual de marca e os arquivos oficiais disponíveis. Comece pedindo uma leitura estruturada, antes de solicitar as peças:

Leia o arquivo de identidade visual anexado e os materiais oficiais da marca. Extraia somente regras que estejam explícitas nos arquivos e organize-as nesta ficha:

  • nome da marca e forma de escrever;
  • cores oficiais e códigos, se informados;
  • fontes e hierarquia tipográfica, se informadas;
  • versões e regras de aplicação do logotipo;
  • margens, áreas de proteção e usos proibidos;
  • estilo de fotografia, ilustração, ícones e formas;
  • tom de voz e exemplos de linguagem;
  • regras específicas para banners, slides ou redes sociais.

Para cada regra, indique de qual arquivo e página ou trecho ela veio. Separe fatos explícitos de sugestões. Se a informação estiver ausente, escreva “não informado”; não deduza nem invente. Ao final, liste dúvidas que devo resolver antes de criar materiais.

Revise a ficha e corrija qualquer leitura equivocada. Guarde-a junto dos arquivos oficiais; ela será a referência comum para os próximos pedidos. O resumo ajuda a reutilizar as regras, mas não substitui o manual original quando houver dúvida.

Etapa 2 — Teste a ficha em peças diferentes

Substitua os campos entre colchetes pelas informações da atividade. Anexe novamente a ficha, o manual e o arquivo oficial do logotipo ou dos elementos gráficos que a peça exigir.

Prompt A — Banner

Usando a ficha de identidade visual e os arquivos oficiais anexados, crie uma proposta de banner para [canal ou local de publicação].

Objetivo: [o que a peça deve comunicar].
Público: [para quem].
Texto obrigatório: [título, data, chamada ou link].
Formato: [largura × altura ou proporção].
Elementos que precisam aparecer: [itens].

Aplique as regras da marca para cores, tipografia, logotipo, imagens, formas e tom de voz. Use o logotipo oficial fornecido sem redesenhá-lo, deformá-lo ou trocar suas cores. Não invente slogans, ícones proprietários ou elementos da identidade. Se algum requisito entrar em conflito com o manual, explique o conflito antes de propor uma solução. Antes de concluir, liste as regras da marca que aplicou e as que não conseguiu confirmar.

Prompt B — Apresentação

Usando a ficha de identidade visual e os arquivos oficiais anexados, planeje uma apresentação de [número] slides sobre [tema], para [público], com o objetivo de objetivo.

Primeiro, apresente o roteiro slide a slide com título, mensagem principal e conteúdo essencial. Depois, proponha o sistema visual: capa, layouts de conteúdo, uso de imagens, gráficos, cores e tipografia, sempre de acordo com o manual. Mantenha consistência entre os slides e preserve boa legibilidade. Não invente dados nem altere o logotipo. Sinalize informações que estejam faltando. Ao final, faça uma checagem do roteiro e do sistema visual contra as regras da ficha.

Prompt C — Outra peça (cartaz, folheto ou publicação social)

Crie uma proposta de [tipo de peça] para [canal ou contexto], destinada a [público], com a mensagem [mensagem principal] e a chamada para ação [CTA].

Considere o formato [dimensões ou proporção] e os arquivos de identidade visual anexados. Use apenas cores, fontes, versões do logotipo e elementos gráficos autorizados no manual. Organize a informação para leitura rápida e mantenha o texto fornecido sem alterações, salvo se eu pedir uma revisão. Se o manual não especificar uma regra necessária, informe a lacuna em vez de inventar.

Etapa 3 — Confira a consistência

Para cada proposta, peça uma auditoria separada:

Compare esta peça com a ficha e com o manual de identidade visual. Apresente uma tabela com: regra da marca, evidência no material de referência, como a peça atende à regra e status (atende, revisar ou não verificável). Confira especialmente logotipo, cores, tipografia, contraste, tom de voz e elementos não autorizados. Não considere uma regra atendida sem evidência. Termine com as correções prioritárias.

A IA pode interpretar o manual de forma incompleta. Confira especialmente códigos de cor, fontes, margens e versões do logotipo. Quando a aplicação final depender de texto exato ou de um logotipo sem distorções, prefira inserir ou ajustar esses elementos no editor de apresentação ou de design usando os arquivos oficiais.

Atividade prática

  1. Escolha um manual de marca ou uma identidade visual pública disponibilizada para estudo.
  2. Gere a ficha consultável e confira pelo menos cinco regras diretamente no arquivo original.
  3. Use a mesma ficha para solicitar um banner e uma capa de apresentação.
  4. Compare as peças: o que permaneceu coerente? O que variou? Alguma regra foi inventada ou ignorada?
  5. Faça a auditoria com o prompt da Etapa 3 e corrija as peças.

Pergunta para reflexão: como podemos manter uma identidade visual consistente em formatos diferentes sem obrigar todos os materiais a terem o mesmo layout?

4. Padronizar slides no Gemini Notebook

Objetivo

Testar se uma ficha de identidade visual em JSON ajuda a manter uma linguagem visual coerente entre apresentações criadas no Studio do Gemini Notebook. O conteúdo deve vir das fontes do caderno; o JSON orienta a forma visual. O resultado é uma orientação para o modelo, não uma regra de diagramação executada com precisão garantida.

1. Prepare um Design System reutilizável

O exemplo abaixo é um ponto de partida para a atividade. As cores são demonstrativas; antes de usar em materiais institucionais, substitua-as pelas cores oficiais da disciplina ou da instituição.

{
  "design_system_apresentacoes": {
    "paleta": {

2. Configure as instruções do caderno

No Gemini Notebook, procure as configurações ou instruções do caderno e adicione uma orientação permanente como esta:

Atue como designer instrucional. Ao preparar apresentações, use as fontes do caderno para o conteúdo e consulte o Design System em JSON fornecido como referência visual. Mantenha uma hierarquia clara, texto conciso, bom contraste e consistência de paleta e linguagem gráfica. Não invente logotipos nem dados. Se alguma regra visual não puder ser aplicada ou não estiver clara, sinalize isso.

A opção de conversa Personalizado, se disponível na interface, pode ajudar a definir a persona e o estilo das respostas no chat. Não presuma que essa preferência, sozinha, controle todas as escolhas do Studio. Por isso, repita o JSON no prompt do Slide Deck.

3. Gere o Slide Deck com o JSON

  1. Abra o caderno que contém as fontes da aula ou do módulo.
  2. No painel Studio, escolha Slide Deck e abra a personalização pelo ícone de lápis.
  3. Selecione o formato (slides para apresentar ou deck detalhado), o idioma, a extensão e as fontes apropriadas.
  4. Escreva o objetivo e o público da apresentação. Cole o Design System em JSON no campo de instrução visual.
  5. Se a interface oferecer revisão do roteiro ou das notas antes da renderização, revise a sequência e corrija o conteúdo antes de gerar os slides.
  6. Para uma segunda aula, use novamente o mesmo JSON, mas altere tema, público ou objetivo conforme necessário.

Prompt para testar:

Crie um Slide Deck sobre [tema], para [público], com o objetivo de objetivo. Baseie as afirmações nas fontes selecionadas do caderno e não acrescente dados sem suporte. Aplique o Design System abaixo como referência visual para paleta, hierarquia, composição e linguagem gráfica. Mantenha uma mensagem principal por slide, texto legível e diagramas pertinentes. Não invente logotipos ou selos.

[Cole aqui o JSON do Design System.]

Antes de gerar, proponha uma sequência de slides com título e mensagem principal de cada um, se a opção de revisão estiver disponível.

4. Compare e verifique

Para testar se a ficha ajuda, crie duas versões a partir do mesmo conteúdo e formato: uma com a instrução padrão e outra com o JSON. Depois, use a mesma ficha em uma apresentação sobre outro tema. Compare os resultados lado a lado.

  • A paleta e a linguagem gráfica permanecem reconhecíveis entre as apresentações?
  • A hierarquia visual é semelhante, mesmo quando o layout dos slides varia?
  • As ilustrações ajudam a explicar o conteúdo ou são apenas decorativas?
  • O texto factual está sustentado pelas fontes selecionadas?
  • Surgiram logotipos, dados, cores ou elementos que não foram fornecidos?
  • Quais regras do JSON foram seguidas, parcialmente seguidas ou ignoradas?

Registre exemplos concretos de slides para cada conclusão. Se uma cor exata, uma fonte específica ou o uso correto de um logotipo for obrigatório, confira o arquivo exportado e finalize esses elementos em um editor de apresentações com os ativos oficiais. Apresentações geradas por IA podem conter falhas visuais ou factuais; revise o material antes de usar ou compartilhar. Atividade prática (10 a 15 minutos)

  1. Escolha fontes de um tema que já esteja no caderno.
  2. Gere uma primeira apresentação com as opções padrão e guarde o resultado.
  3. Gere uma segunda versão do mesmo tema, incluindo o JSON no prompt de personalização.
  4. Gere uma apresentação de outro tema usando a mesma ficha.
  5. Compare as três versões pela paleta, hierarquia, linguagem gráfica, legibilidade e fidelidade às fontes. Registre uma evidência e uma limitação do método.

Conclusão esperada: o JSON pode tornar as instruções de estilo mais claras e reutilizáveis. O teste deve mostrar em que medida o Gemini Notebook mantém a consistência e quais ajustes ainda exigem revisão humana.
